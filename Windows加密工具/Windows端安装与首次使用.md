# Windows 加密工具：安装与首次使用

## 1. 选择安装文件

- `安装包/LicenseProtector-Windows加密工具-Setup.exe`：正常安装版，推荐使用。双击运行，按向导完成安装；默认是当前 Windows 用户安装，不需要修改服务器或 PHP 配置。
- `安装包/LicenseProtector-Windows-Encryptor.exe`：便携版，不安装，双击即可运行。

不要把这两个 Windows 程序上传到 Linux 服务器。服务器端使用的是 Windows 工具生成的 Linux 项目部署包。

## 2. 首次启动

首次运行时，工具会初始化厂商公钥和私钥，并将它们保存在当前 Windows 用户的数据目录。以后继续使用同一套厂商身份，不要删除或重新生成这对密钥；建议将密钥目录安全备份。

厂商私钥只留在 Windows 端，绝不能上传到 Linux 服务器。Windows 工具会按项目准备并复用运行密钥，生成的 Linux 项目部署 ZIP 才包含服务器所需的运行密钥。

## 3. 生成项目交付包

1. 选择原有 PHP 项目目录，不要移动或改写你填写的项目路径。
2. 选择 `Native Loader 加密包`，然后勾选需要保护的 PHP 文件。只会加密勾选的文件；选择目录时会跳过 `vendor` 等依赖目录。
3. 添加授权域名或 IPv4，设置产品版本、最低 PHP 版本，并填写一个与源项目分开的交付输出目录。
4. 点击生成交付包。输出包含 PHP 项目交付内容和项目专属 Linux 部署 ZIP。

### Hyperf 项目注意

当前 Loader shim 不能保留 Hyperf 对类属性注入等源码元数据的扫描结果。因此不要加密 `app/Controller/AbstractController.php`，也不要加密含 `#[Inject]`、注解、AOP 元数据的类。否则可能出现属性未初始化或 HTTP 500。先只选择不承担框架扫描/注入职责的业务 PHP 文件。

## 4. 交付边界

- PHP 加密交付内容放回原项目的对应部署位置。
- 生成的 Linux 部署 ZIP 只通过可信渠道传给服务器管理员；不要放进网站可公开访问的目录。
- 不要上传 `vendor_private.pem`，也不要把厂商私钥提交到代码仓库。
- 保存好厂商密钥备份和每个项目的 Linux 部署 ZIP；丢失对应运行密钥后，已有加密包将无法解密。
